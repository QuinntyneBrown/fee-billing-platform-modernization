The interview point

SDK-style net472 makes the build modern. It doesn't move anything to .NET 10.

What the conversion silently drops

  • install.ps1 scripts don't run under PackageReference
  • Content transforms (like editing Web.config on install) don't run either
  • Transitive dependencies go from explicit to implicit
  • Binding redirects need regenerating
  • Visual Studio's migration command doesn't support every project type: check first

New code isn't automatically clean

  • FeeBilling.Modern.slnx pulls its own graph: EF Core, OpenTelemetry, Testcontainers…
  • An advisory against any of those is your problem from day one
  • --outdated shows how far behind each package is: a rough measure of upgrade effort

Write the policy down

Modern code

Fail the build on high and critical. Warnings as errors makes it easy.

Legacy

Fix critical findings now. It's still production.

"We're migrating anyway" is not a reason to leave a critical advisory in production for a year.

Licences matter as much as vulnerabilities

  • Per the training plan, MediatR and AutoMapper moved to commercial licences in 2025 (check current terms)
  • Check the licence before adding a dependency
  • If terms change: pin the last acceptable version, or replace it
  • A CQRS dispatcher is about 50 lines of your own code
  • PDF and imaging libraries are next: lesson 21

The tools

.NET Upgrade Assistant

Microsoft's tool for this work

GitHub Copilot app modernization

Where Microsoft has been steering people

This changes quickly: check current status before citing either.

What they do, and what they don't

They do

  • Convert project files to SDK-style
  • Change target frameworks
  • Update package references
  • Some mechanical code fixes

They don't

  • Choose CoreWCF vs REST
  • Replace MSDTC with an outbox
  • Decide who owns the schema
  • Prove the invoice matches to the cent

Tools do the project-file grunt work. People do the architecture and the parity proof.

In an interview, say clearly what the tool did and what you did.

Traps

  • Treating the project conversion as the migration
  • Losing packages.config behaviour silently
  • Hiding the signal: suppressing NU1701
  • Auditing only direct dependencies
  • Deferring legacy security fixes "because we're migrating"
  • Adding a package without checking its licence
  • Expecting a tool to make architecture decisions
Interview drill

Five questions

After each question, pause and answer out loud. Then compare with the model answer.

Question 1 of 5

How do you assess a .NET Framework codebase before migrating it?

Answer out loud.

Model answer
  • Project and package inventory
  • Search for Framework-only APIs, grouped by the work that fixes them
  • Vulnerability and licence audit, including transitive dependencies
  • Output: triage table, API counts, audit policy, risk register. Then a plan
Question 2 of 5

What does Upgrade Assistant, or Copilot app modernization, do and not do?

Answer out loud.

Model answer
  • Does: project files, target frameworks, packages, mechanical fixes
  • Doesn't: CoreWCF vs REST, outbox vs distributed transaction, parity proof
  • Tools do the grunt work; people do the design
  • Check which tool Microsoft currently recommends
Question 3 of 5

How do you manage package versions across twenty projects?

Answer out loud.

Model answer
  • Central Package Management: one Directory.Packages.props, versionless references
  • Transitive pinning to force patched transitive versions
  • Shared settings in Directory.Build.props
  • FeeBilling: modern uses both; legacy opts out with its own props files
Question 4 of 5

A package you depend on changed to a commercial licence. What do you do?

Answer out loud.

Model answer
  • Catch it before adding the package: licences checked like vulnerabilities
  • Pin the last acceptable version while evaluating a replacement
  • Replace it if the terms don't work
  • MediatR and AutoMapper: a CQRS dispatcher is ~50 lines
Question 5 of 5

What's the risk in converting packages.config to package references?

Answer out loud.

Model answer
  • Install scripts and content transforms stop running, silently
  • Transitive dependencies go implicit: versions can shift
  • Binding redirects need regenerating
  • Diff the resolved graph and config files; the conversion isn't the migration
