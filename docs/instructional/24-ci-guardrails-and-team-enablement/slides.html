A banned-API analyzer

  • Package: Microsoft.CodeAnalysis.BannedApiAnalyzers
  • A text file, BannedSymbols.txt, lists what new code must not use
  • Reports rule RS0030 wherever they appear
  • TreatWarningsAsErrors is already on: a build failure

Add it once, for every project

Sketch · target design · Directory.Packages.props
<GlobalPackageReference Include="Microsoft.CodeAnalysis.BannedApiAnalyzers" Version="x.y.z" />
Sketch · target design · Directory.Build.props
<ItemGroup>
  <AdditionalFiles Include="$(MSBuildThisFileDirectory)BannedSymbols.txt" />
</ItemGroup>

Pin the analyzer version; look it up on the day rather than copying one from a blog.

One surprising entry

Surely HttpContext.Current can't compile in modern .NET?

It does, if the project references the SystemWebAdapters package.

So ban it explicitly.

Ban at the overload level

Sketch · target design · BannedSymbols.txt
M:System.Math.Round(System.Decimal);Pass MidpointRounding explicitly: it's a decision
M:System.Math.Round(System.Decimal,System.Int32);Pass MidpointRounding explicitly: it's a decision
M:System.Math.Round(System.Double,System.Int32);Money is decimal

Allowed: the overload with an explicit MidpointRounding.

Banning Math.Round entirely would just train people to suppress the rule.

Keep the domain pure

Sketch · target design · architecture test
[Fact]
public void Domain_has_no_infrastructure_references()
{
    string[] forbidden = ["Microsoft.EntityFrameworkCore", "Microsoft.AspNetCore", "log4net", "System.Web"];
    var references = typeof(FeeSchedule).Assembly.GetReferencedAssemblies().Select(a => a.Name ?? "");
    Assert.DoesNotContain(references, name => forbidden.Any(f => name.StartsWith(f, StringComparison.Ordinal)));
}

A burn-down on every CI run

Sketch · target design · CI step
for pattern in 'HttpContext\.Current' 'ConfigurationManager' 'BinaryFormatter' \
               'TransactionScope' 'System\.Drawing' 'DateTime\.Now'; do
  count=$(git grep -c -E "$pattern" -- legacy src | awk -F: '{ s += $2 } END { print s + 0 }')
  echo "| $pattern | $count |" >> "$GITHUB_STEP_SUMMARY"
done

HttpContext.Current falling from dozens to zero is a chart leadership understands. A jump back up names the pull request.

Don't fall back on "I'd document things". Name three concrete assets and one guardrail, each with a reason.

Three assets, one guardrail

  • Fix Accounts API first and make it the reference slice: whatever exists gets copied
  • A service template: health checks, telemetry, auth, Testcontainers from day one
  • An ADR log: decisions don't get re-argued in pull requests
  • A banned-API analyzer with teaching messages: the traps fail the build
Close with

Pair on each developer's first slice, review the second, and step back.

You think about the team, not just the code: that's what the SME part of the role is testing.

Traps

  • continue-on-error as a permanent state
  • Banning too broadly, which trains people to suppress rules
  • Silenced warnings spreading from legacy into new code
  • A reference implementation with bugs, copied everywhere
  • Vulnerability audits failing unrelated pull requests
  • Golden files anyone can regenerate without review
  • Measuring lines of code instead of traffic and legacy APIs
  • The subject-matter expert as a bottleneck

Four questions

Question 1 of 4

How would you make other developers productive on the migration?

Answer out loud.

Model answer
  • A reference vertical slice, known bugs fixed first
  • A template for new services, already wired
  • An ADR log; a playbook with the per-slice checklist and traps
  • Pair on the first slice, review the second, step back
Question 2 of 4

How do you stop people from reintroducing legacy patterns?

Answer out loud.

Model answer
  • Banned-API analyzer, messages that say what to use instead
  • Ban at the overload level (rounding without a midpoint mode)
  • Architecture tests; a parity gate; code owners on correctness files
  • Exceptions need a written justification, visible in review
Question 3 of 4

What goes in CI for a migration?

Answer out loud.

Model answer
  • Both stacks building; modern tests on real infrastructure
  • A gating legacy subset; the rest quarantined
  • Required parity check; golden files under code-owner review
  • Analyzers, architecture tests, dependency and licence checks, a burn-down report
Question 4 of 4

How do you measure migration progress?

Answer out loud.

Model answer
  • Fallback-route traffic trending to zero
  • Legacy API usages over time
  • Slices cut over; open parity differences
  • Firms billed by the modern engine
