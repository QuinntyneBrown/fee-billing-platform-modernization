Watch the provider order

A provider added after CreateBuilder comes after the environment variables, so it overrides them.

Decide deliberately whether an operator's environment variable can override central configuration.

  • Web.Release.config and Web.ClientX.config: production SQL logins with passwords

Rotate. Then move them.

  1. Rotate every one. Deleting doesn't un-leak: it's in git history and every clone

  3. App Configuration Key Vault references: one configuration tree

Fail at startup, not at invoice 40,000

legacy/FeeBilling.Invoicing/InvoicePdfRenderer.cs
var path = ConfigurationManager.AppSettings["Invoice.LogoPath"];

Read lazily, on the first PDF. A bad path isn't found until someone asks for an invoice.

A bad value should stop startup, not break the forty-thousandth invoice PDF.

One INFO line per calculation

legacy/FeeBilling.Core/FeeCalculator.cs
Log.Info("Fee for " + accountId + " = " + fee);

Tens of thousands of lines of text for one large firm's run.

What's wrong with it

  1. Unsearchable text. "Every fee over $1,000" or "every line for account 1001" means parsing strings.
  2. Allocates even when INFO is off. The concatenation runs regardless.

Message templates and source-generated logging

Sketch · target design
logger.LogInformation("Fee calculated for account {AccountId}: {Fee}", accountId, fee);

[LoggerMessage(EventId = 1001, Level = LogLevel.Debug,
    Message = "Fee calculated for account {AccountId}: {Fee}")]
static partial void FeeCalculated(ILogger logger, int accountId, decimal fee);
  • AccountId and Fee stay named properties you can query and aggregate
  • Generated code: level check, no boxing, a stable event ID
  • Demote the per-account line to DEBUG; replace it with a metric

W3C trace context, hop by hop

One trace ID finds every line

Sketch · additive change in legacy/FeeBilling.Web/Global.asax.cs
protected void Application_BeginRequest(object sender, EventArgs e)
{
    var traceparent = Request.Headers["traceparent"];   // 00-{trace-id}-{parent-id}-{flags}
    if (traceparent != null && traceparent.Length >= 35)
        log4net.LogicalThreadContext.Properties["TraceId"] = traceparent.Substring(3, 32);
}

Then print the property in the log4net pattern.

Interview drill

Five questions

After each question, pause and answer out loud. Then compare with the model answer.

Question 1 of 5

What replaces Web.config and config transforms?

Answer out loud.

Model answer
  • Layered providers: appsettings, environment file, environment variables
  • App Configuration with a label per client, not a transform per client
  • Secrets in Key Vault with managed identity; user secrets locally
  • Typed options validated at startup. Build once.
Question 2 of 5

How do you migrate configuration safely?

Answer out loud.

Model answer
  • Inventory: grep every key (web app reads 2 of 10)
  • Delete dead keys rather than migrating them
  • Business rules like day-count basis → versioned data
  • Find flags read by a different process; rotate committed secrets
Question 3 of 5

Structured logging or string logging?

Answer out loud.

Model answer
  • Structured: named properties you can query and aggregate
  • Concatenation: unsearchable, allocates even when off
  • LoggerMessage source generator removes the overhead
  • Classify and redact PII: it's all indexed
Question 4 of 5

How do you trace a request across old and new systems?

Answer out loud.

Model answer
  • W3C trace context: traceparent propagated by instrumentation
  • The gateway forwards it
  • Outbox: store the context in the row, restore it in the consumer
  • Legacy: read the header, trace ID into the log4net context
Question 5 of 5

What would you put on the billing dashboard?

Answer out loud.

Model answer
  • Run duration, accounts/second, failed and quarantined counts
  • Dead-letter depth, parity differences, error rate by firm
  • Tagged by firm, never by account
  • Alert: throughput drop, dead letters, unexplained parity diffs
