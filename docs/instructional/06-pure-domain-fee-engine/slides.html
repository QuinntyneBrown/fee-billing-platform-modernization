FeeBilling modernization · Lesson 06

A Pure-Domain
Fee Engine

From static calculators to an engine you can test, prove and audit

What we're replacing

A handful of static classes that reach into the web request, the ASP.NET cache, a stored procedure and a logging library. One is a copy-paste of another.

  • Can't be unit tested
  • Can't run outside IIS without a fake request
  • Can't run in a Linux container at all

The questions this lesson answers

  • How do you make static, untestable logic testable without changing its behaviour?
  • Where does the clock go?
  • Strategy pattern or a switch statement?
  • How do you keep a domain layer pure over time?
  • How do you make every calculation auditable?
Target architecture · principle 1

The domain is pure. No Entity Framework, no ASP.NET, no logging framework, no clock. Inputs in, invoice lines out.

That's what makes parity testing possible.

One strategy per schedule type

public interface IFeeStrategy
{
    FeeScheduleType Handles { get; }
    AnnualFeeResult CalculateAnnual(Money billableAum, FeeSchedule schedule);

public sealed class FeeEngine(IEnumerable<IFeeStrategy> strategies, BillingPolicy policy)
{
    public FeeResult Calculate(FeeRequest request);   // pure, no I/O, no clock
}

Tiered · Blended · Flat · Householded, all injected; the engine picks by schedule type.

The key insight: return tier lines

legacy/FeeBilling.Core/FeeCalculator.cs
fee += Math.Round(span * (double)tier.AnnualRate / 4, 2);  // double + per-tier rounding + /4
  • A strategy that returns one annual number can never reproduce per-tier rounding
  • Strategies return tier lines: band, span, rate
  • The engine rounds per tier (Legacy) or once at the end (Corrected)

Legacy's cache is a correctness bug

var aum = HttpRuntime.Cache[cacheKey] as double?;

Thirty minutes, process-wide: a recalculation can use stale AUM.

Where does the clock go?

Not in the domain. The engine takes dates as inputs.

  • The application layer asks TimeProvider what today is
  • netstandard2.0 has Microsoft.Bcl.TimeProvider, but better to keep the clock out of Domain entirely
legacy/FeeBilling.Core/QuarterHelper.cs
/// <summary>The most recent quarter end on or before today (server local time).</summary>
public static DateTime LastQuarterEnd()
{
    var today = DateTime.Now.Date;
    return IsQuarterEnd(today) ? today : GetQuarterStart(today).AddDays(-1);
}

The blended boundary

legacy/FeeBilling.Core/BlendedFeeCalculator.cs
// Blended: whole AUM at the rate of the highest tier reached
double rate = 0;
foreach (var tier in account.FeeSchedule.Tiers.OrderBy(t => t.LowerBound))
{
    if (aum.Value > (double)tier.LowerBound || tier.LowerBound == 0)
    {
        rate = (double)tier.AnnualRate;
    }
}

Exactly $1,000,000 stays at 1%. "Cleaning it up" to ≥ drops that quarter's fee by $625.

Interview drill

Five questions

After each question, pause and answer out loud. Then compare with the model answer.

Question 1 of 5

How do you make static, untestable business logic testable without changing its behaviour?

Answer out loud.

Model answer
  • Capture behaviour with a golden master, through a seam, untouched
  • Write a new pure implementation beside it
  • Hidden dependencies become explicit inputs: context, stored-procedure AUM, cache, clock
  • Prove equivalence with the Legacy policy, then retire the old code
Question 2 of 5

Where does the clock go?

Answer out loud.

Model answer
  • Not in the domain: period end and opened-on are inputs
  • The edge asks TimeProvider, in the firm's named time zone
  • Tests use FakeTimeProvider
  • Containers run in UTC: near midnight you could bill the wrong quarter
Question 3 of 5

Strategy pattern or a switch statement?

Answer out loud.

Model answer
  • Strategies when each variant has real behaviour and its own tests
  • Selected by schedule type, from dependency injection
  • A switch is fine for a trivial mapping
  • Legacy's smell was the copy-paste; strategies return tier lines
Question 4 of 5

How do you keep a domain layer pure over time?

Answer out loud.

Model answer
  • No package references in the domain project
  • Architecture test: no EF, ASP.NET Core or logging dependencies
  • Banned-API analyzer for DateTime.Now
  • An ADR that code review can enforce
Question 5 of 5

How do you make every calculation auditable?

Answer out loud.

Model answer
  • A calculation trace on every result, stored with the invoice line
  • Tiers, AUM, basis and factor, rounding mode and points, minimum, pro-rating
  • Used by compliance, the parity report and the review screen
